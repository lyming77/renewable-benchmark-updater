# 新能源交易对标更新

上传上一版分析工作簿和一份或多份最新收集表，下载本次更新后的分析工作簿。

主要流程：按字段名称识别不同公司布局，交叉补空并列出冲突；规范明确的容量单位；按组成关系核对总量、总费和价格；重建任意选月的完整样本利用小时；保留原 WPS 透视表和切片器。

## 本地运行

使用 Python 3.12，在此目录执行：

```bash
python -m pip install -r requirements.txt
streamlit run streamlit_app.py
```

## 部署到 Streamlit Community Cloud

将本目录的程序上传到一个 GitHub 仓库，在 Streamlit Cloud 选择该仓库和分支，入口为 `streamlit_app.py`，Python 版本选择 3.12。程序不需要 API 密钥、数据库或外部模型服务。

官方部署说明：https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/deploy

不要把业务原始文件、生成的分析表、上传目录或凭证提交到 GitHub。程序从上传控件读取数据，结果只保留在当前会话内存中供下载。

## 输入与处理口径

- 上一版分析表：此前生成的、带 `Sheet2` 明细和 `Sheet5` 原生透视表的 `.xlsx`。
- 最新收集表：同一年度的 `.xlsx`，支持多公司分表和规范长表。列数不必一致，但应有可识别的字段名称、月份和场站。
- 默认只补空值，保留旧的非空数值。可以选择采用新数值，覆盖行为逐项记录。真正的零值不会被视为缺失。
- 同名分期、单位不明、多个来源相互矛盾等情况会列入待核对，不会凭企业名或容量大小猜测。
- 利用小时使用实际上网电量（MWh）与装机容量（MW）。只有所选各月都有有效电量及正容量的场站才纳入。容量按月日历天数近似加权，交易指标保留筛选范围内全部记录。
- 每次生成重建月份控制行、原生缓存和辅助字段。生成后若手工增改原始数据，请重新上传生成。
- 新版本的本次更新记录包含本轮变更和问题，旧审计页作为旧版本历史快照保留。
- 上传文件单份不超过 50 MB，最多 15 份收集表，合计不超过 120 MB。仅支持单年度，不支持宏工作簿。
- 若身份无法唯一识别、模板不兼容或原生透视字段数超出兼容预算，程序会停止生成并说明原因。

## 验证

```bash
python -m pip install pytest
python -m pytest -q tests
```

测试与仓库不包含真实企业交易数据。端到端验收应使用用户本地模板和收集表，并在 WPS 打开输出结果、刷新及任意多选月份，核对同一筛选下的交易与利用小时。
